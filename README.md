# 南京麻将 · 好友局

一个可以直接发链接给微信好友、四个人在线打南京麻将的 H5 应用。服务端权威判定，**发牌过程可事后验算**，AI 补位，手机竖屏即开即玩。

牌面按传统牙牌画风逐张重绘（SVG，万/条/筒/字/花 34 种，筒子按参考图排布），带古筝风格背景音乐、碰/杠/胡特效，支持**赛前设置每人初始积分、按番结算**；每家的花牌逐张贴在自己座位边沿。

牌桌**强制横屏**（竖屏拿手机时会自动转 90°，把手机横过来即可正面看）；**打出牌会用 AI 女声报牌**（本地语音包，不依赖网络）；**每回合限时 2 分钟**，超时自动打出一张，随时可以暂停/继续。

> 纯娱乐，不含任何真实货币或兑换。

## 一、跑起来

```bash
npm install
npm start
# 打开 http://localhost:3000
```

- **单人练习**：直接对战 3 个 AI，不需要服务器逻辑以外的任何配置。
- **横屏**：牌桌按横屏设计，手机竖着拿时页面整体旋转 90°，把手机横过来就是正视角；系统允许自动旋转时则直接用横屏铺满。
- **好友联机**：创建房间 → 复制邀请链接 → 好友点开即入座。不足 4 人自动 AI 补位。
- **开局前**：在大厅选择每人初始积分（500 / 1000 / 2000 / 5000），整局累计，可连续多局。
- **背景音乐**：右上角 ♪ 一键开关，设置会记住；音乐与音效全部由 Web Audio 实时合成。
- **报牌女声**：右上角「报牌」开关。打出牌时念出牌名（如「五万」「东风」），语音包是 34 张牌的 mp3，随项目一起部署，首次进入后后台预加载，弱网也不卡。
- **限时与暂停**：每人出牌限时 2 分钟（响应碰杠胡 15 秒），到点自动打出；点「暂停」全桌冻结，任何一位好友都能点「继续」恢复。

要求 Node.js ≥ 16。

## 二、怎么让微信好友点开就能玩

微信里打开的网页必须是 **https**（否则语音、剪贴板和 WebSocket 都会被限制）。把这个 Node 服务部署到任意支持 Node 的平台，拿到 https 域名即可。

| 方式 | 操作 | 适合 |
|---|---|---|
| Railway / Render / Fly.io | 连 Git 仓库，自动 `npm start`，自动分配 https 域名 | 最快，零运维 |
| 腾讯云轻量 / 阿里云 ECS | 装 Node + `pm2 start server.js`，Nginx 反代 + 证书 | 国内访问快 |
| 自己的服务器 | 同上 | 完全可控 |

部署好之后：

1. 手机打开 `https://你的域名`
2. 点「创建房间」，得到 4 位房间码
3. 点「复制邀请链接」，粘贴到微信群
4. 好友点链接 → 输入昵称 → 自动入座
5. 房主点「开始游戏」

链接形如 `https://你的域名/?room=ABCD`，好友中途掉线重进同一个链接即可回到牌桌（席位由 AI 暂时接管）。

iOS/Android 浏览器菜单里的「添加到主屏幕」，可以获得接近原生 App 的全屏体验。

## 三、规则（南京麻将主流打法）

- **牌**：144 张 = 万/条/筒 各 36 + 东南西北 16 + 花牌 20（中发白各 4、春夏秋冬梅兰竹菊各 1）
- **可碰、可杠，不可吃**
- **起手**：每人 13 张，庄家 14 张；摸到花牌立即从牌尾补牌，花牌亮出计「硬花」
- **小胡限制**：非门清且硬花不足 4 张不能胡（防屁胡）
- **番种**：平胡、门清、碰碰胡、混一色、清一色、七对 / 豪华七对 / 超豪华七对、全球独钓、无花果、杠上开花、天胡、地胡
- **计番**：底 20 番 + 硬花数 + 软花（明杠 1 / 暗杠 2）+ 番种番数（门清 20、七对 80、清一色 60……）
- **结算**：1 番 = 1 分。自摸三家各付，点炮由放炮者一家付；杠即时结算（明杠 20 分、暗杠每家 10 分）
- **积分**：开局设置初始分，每局结算后累计，结算页同时显示「本局输赢」和「结余」
- **连庄**：胡牌者坐庄，荒庄连庄且积分不变

规则在代码里都写在 `public/core.js` 的 `evaluateWin()` 中，想改番数直接改那张表即可。

## 四、发牌为什么是「真随机」

这是这个项目唯一值得展开讲的部分。

### 1. 随机源
不用 `Math.random()`。洗牌用的整数来自：

- 浏览器：`crypto.getRandomValues`
- Node：`crypto.randomBytes(32)`

两者都是操作系统级 CSPRNG，密码学强度，不可预测、不可回推。

### 2. 洗牌算法
Fisher–Yates 原地洗牌，每个位置用 **拒绝采样**（rejection sampling）取 `[0, n)` 的整数：

```js
const limit = max - (max % n);
do { v = nextBytes(); } while (v >= limit);
return v % n;
```

这样消除了 `random() % n` 带来的取模偏差 —— 144 张牌不是 2 的幂，直接用取模会让前 16 张牌出现概率偏高。

### 3. 没有人能单独控制牌序
最终种子不是服务端一个人说了算：

```
seed = SHA-256( serverSeed : salt0 : salt1 : salt2 : salt3 | round:N )
```

`salt0..3` 是四家各自的随机盐值，服务端只是把它们拼在一起。任何一方都无法预测或操纵最终结果。

### 4. 承诺—揭示（commit–reveal）
- 开局：服务端先广播 `commit = SHA-256(serverSeed|round)`，此时种子本身保密
- 结束：公布 `serverSeed` 和四个 salt
- 任何人可以本地重算：`seed → 洗牌 → SHA-256(牌墙)`，与开局公布的 `wallHash` 比对

牌局结束后点结算页的「验证发牌」，页面会当场重算并显示两个哈希是否一致。只要对不上，就说明发牌被改过。

因为 `commit` 在开局就已固定，服务端事后无法换一个对自己有利的种子；而种子又包含四家的盐，单方也无法提前算牌。

### 5. 已做的统计检验
`npm test` 里有一个卡方检验：对 14400 次独立洗牌统计首张牌的分布，与理论概率（每张牌出现概率 = 它在牌堆中的张数 / 144）比较。自由度 41，p=0.001 的临界值约 75，实测卡方在 30–45 之间波动，通过。

## 五、为什么不做微信小程序

棋牌类目在微信属于**限制类目**：

- 需要企业主体 + 《网络文化经营许可证》等资质
- 涉及棋牌游戏还需要版号
- 个人开发者账号无法开通该服务类目，提审必然被拒

所以对个人或小团队来说，**H5 链接是最现实的路径**：微信内直接打开、可转发到群、可添加到主屏幕，体验和小程序差别不大，且不受类目审核限制。

如果日后有企业资质，再用 `web-view` 把同一个 H5 包一层小程序壳即可，前端代码几乎不用改。

> 注意：任何形式的线上棋牌若涉及真实货币兑换，都属于违法。本项目仅作娱乐用途。

## 六、目录结构

```
nanjing-mahjong/
├── server.js            # HTTP 静态服务 + WebSocket 房间 + 超时托管
├── package.json
├── test.js              # 引擎测试（牌型、番型、随机均匀性、200 局模拟）
└── public/
    ├── index.html       # 大厅 / 房间 / 牌桌 / 结算 / 验证
    ├── style.css
    ├── core.js          # 牌、胡牌判定、听牌、番型、AI（前后端共用）
    ├── rng.js           # SHA-256、DRBG、commit-reveal
    ├── game.js          # 状态机（服务端权威，单机时在浏览器里跑同一套）
    ├── audio.js         # 背景音乐/音效合成 + 报牌语音播放
    ├── fx.js            # 碰/杠/胡特效
    ├── tiles.js         # 34 种牌面 SVG
    ├── voice/           # 34 张牌名 + 超时 的 AI 女声 mp3（共约 230KB）
    └── app.js           # 交互与渲染
```

`core.js` / `rng.js` / `game.js` 都是 UMD 写法，Node 里 `require`、浏览器里挂全局，同一份逻辑两端复用 —— 单机模式和联机模式跑的是**完全相同的判定代码**，不会出现「本地能胡、联网不能胡」的问题。

## 七、常见问题

**好友进不来？**
检查链接是否是 https，以及房间码是否输错（4 位，不含 0/O/1/I）。

**中途退出会怎样？**
席位由 AI 接管，牌局继续。重进同一个房间链接可以拿回座位继续打。

**超时时间是 2 分钟，想改怎么办？**
启动时加环境变量即可，例如 `TURN_SEC=180 CLAIM_SEC=20 node server.js`。

**能改成 108 张（不带花牌）吗？**
改 `core.js` 的 `buildWall()`，同时把 `isFlower()` 与番型里的花牌逻辑去掉。但那样就不是南京麻将了。

**能加语音/表情吗？**
可以，但需要额外接 WebRTC 或第三方 IM SDK，且 https 与麦克风权限是前提。
